# ADR 0010 · 投递制：种子投给多人，候选表态，发起人挑到收满

- 状态：已采纳
- 日期：2026-08-12
- 相关：ADR 0004（复用 A2A 生命周期）、不变量 3（成局前只有提案，没有关系）、issue #26
- 触发：PRD v2 的「投递制」和当时已实现的「整组求解 + 全员点头」是两套流程，
  产品负责人判定 PRD 这一处比已有实现对

## 背景

旧链路：清算窗口到点 → 整组求解产出 2–3 支候选队 → 发起人挑一支 →
队里每个人各自点头 → 全票才成局。

它把发起人的勇气**花在一次抛硬币上**：挑一支队，然后等对方理不理你。
而"石沉大海"正是这个产品要消灭的第二个痛点——第一个是"不知道找谁"。

## 决定

**投给多人 → 候选各自表态 → 发起人在说过愿意的人里挑 → 收满需要的人数。**

发起人面对的每一个人**都已经说过愿意**。他挑谁就是谁，不用再等一次回音。

### 不采纳 PRD 的「只选一名」

PRD 默认发起人只选一名同行者。**产品负责人明确不采纳**：按种子要的人数
收满为止。一件需要三个人的事只允许选一个，等于让发起人重复三遍整个流程。

### 一对一，不是一支队

每个候选各自一条记录：各自的状态、各自的留言、各自的"为什么投给你"。

这就是它不能塞进 `formation_proposals` 的原因——那张表的 `member_ids`
说的是"一支队的成员"，而这里是一批**互不相干**的人。所以新建
`seed_deliveries`（迁移 0020）。

### 求解器没被删，降级了

从"产出提案"变成"产出排序与理由"（`matching/pick.py`）。

**稳定性检查从这条路上撤掉**：投递制下不存在分区，它判的"没人更想去别的组"
没有对象了。它留在组织者招募那条多席位的路上——那里仍然是整组求解。

> 「稳定性检查未通过的分区不得成为提案」这条红线**没有被放宽**：
> 没有分区的地方谈不上分区的稳定性。有分区的地方它照旧守着。

## 几条写进实现的判断

- **重复投递不覆盖已经答过的。** 说过"这次不感兴趣"的人不该在下一轮清算里
  被重新问一遍——**同一件事问第二遍最伤**。
- **只能答还没答过的。** 改主意靠重新沟通，不靠反复切换按钮：
  发起人已经在据此挑人了。
- **没被选中的人看到的是「这颗种子已经找到同行者」，不是「你没被选上」。**
  前者说的是这颗种子的处境，后者是对他的评价，而这里没有评价。
- **`delivered_since()` 守着清算幂等。** 少了它，同一条需求每跑一次清算就再投给
  几个新人，候选那一侧收到的是一封又一封"有人想找你"，像垃圾邮件。
  （这个洞真的出现过：`_already_proposed` 改投递制后仍在查空掉的提案表。）
- **曝光上限仍然按轮算。** 逐条投递看不见争用，先提交的人会把稀缺角色全占走。
  批量清算买到的唯一东西就是这个。

## 后果

- 「N 颗种子等你看」取代「有 N 件事等你答复」：数的是种子不是提案
- 两块新界面：信箱（被找到的那一侧）、挑人屏（发起的那一侧）
- 「说了愿意不等于已经加入」这句话必须挨着按钮出现——
  不变量 3 说成局前只有提案没有关系，而"愿意"离"加入"还差发起人点一下
