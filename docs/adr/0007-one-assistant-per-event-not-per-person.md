# ADR 0007 · 助手属于「事」，不属于「人」——但「我的助手」这个概念要有

- 状态：已采纳
- 日期：2026-08-12
- 相关：ADR 0003（AI 承重的位置）、ADR 0004（复用 A2A 而非自研协商）、issue #11
- 触发：同一个问题被问了三次——"这个智能体到底是每个人有一个，还是平台上有一个"

## 背景

产品负责人反复问：每人一个智能体，还是平台一个？

前两次的回答是"功能等价"——窗口清算会主动把提案推给你，所以"我的智能体
帮我盯着"这件事已经有了。**那个回答不够好**，因为它答的是另一个问题。

把问题拆开之后很清楚，这里面藏着两件事：

1. **要不要有一个自主体，替我去搜、替我去谈？**
2. **用户视角上有没有「我的助手」这个东西？**

第一个的答案是不要，第二个的答案是要。混在一起答，两边都答不对。

## 决定

### 一、不给每人一个自主 agent

理由是实证的，不是洁癖：

- **首提案偏差。** 微软 Magentic Marketplace 实测：所有模型都严重偏向第一个
  收到的提案，**响应速度相对质量的优势达 10–30 倍**。让 agent 互相谈判，
  赢的是回得快的那个 agent，不是最合适的人
- **每次对话都是一次披露。** 两万人两两协商是 2 亿次对话，2 亿次披露决定
- **选择过载。** 搜索上限 3→100 时福利显著下降（Claude Sonnet 4 从 1800 掉到 600）
- **提示注入。** 自由格式的 agent 间对话是攻击面

所以全局视角的活（谁和谁可能配得上）交给**求解器**，需要授权的活
（要不要露出、答不答应）交给**人**。中间不放一个替人做决定的自主体。

### 二、唯一人格化的 agent 属于共同事件

`FieldAgent` 绑一个共域，拿能力令牌（绑空间、绑用途、绑策略纪元），
永远拿不到改承诺、增删成员、发布素材、批准记忆这四类能力——它们
在类型层就不可表示。

N+1 里的那个 +1 是它。**它不属于任何成员，所以它不代表任何成员说话。**

### 三、「我的助手」是一个概念面，不是一个自主体

用户要的那个东西是真实的：**得让他知道有东西在替他干活。** 它做三件事，
三件都已经建好了，缺的只是一个统一的面：

| 它做的 | 已建于 |
|---|---|
| 帮我把话说清楚（一句话 → 结构化卡，追问不超过两个） | `/intents:compile` |
| 帮我盯着（清算主动把提案推给我） | 窗口清算 + 导航上的「有 N 件事等你答复」 |
| 帮我起草回复（本人 / AI 起草本人过目 / AI 代答） | 代聊三档 |

**它不做的**：不替我谈判、不和别人的 agent 对话、不替我承诺。

这三条边界不是配置项。前两条由架构保证（没有 agent-to-agent 的通道），
第三条由确认门保证（承诺只接受真人签名的命令）。

## 后果

- 要补的是**一个面**，不是一个新的运行时。它把已有的三件事收在一起，
  让用户看得见"有东西在替我干活"
- 界面上仍然不出现「智能体」「代理」这些词（07 §2 的映射表里，
  「意图使者 / 个人代理」是**完全不出现**）。这个面叫什么由产品语言决定，
  但它不叫 agent
- ADR 0004 的判断不变：受限协商仍然复用 A2A 的 Task 生命周期，
  七种消息没有一种构成同意

## 什么情况下应该推翻这条

如果实测发现用户大量抱怨"我得一直自己来看有没有新机会"，说明"帮我盯着"
这条做得不够主动。那时候的正确做法是**加通知**（推送 / 邮件 / 站内信），
不是加一个替他决定的自主体——问题是"他不知道"，不是"他不会判断"。
