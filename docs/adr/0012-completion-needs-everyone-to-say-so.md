# ADR 0012 · 一件事完成，必须每个成员各自说过

- 状态：已采纳
- 日期：2026-08-12
- 相关：不变量 6（共域因真实行动证据生长）、不变量 11、ADR 0009、issue #23
- 触发：走查走到「做完之后还能不能长出下一件」时发现——
  `done_marks` 有五条记录，而事件仍然是 `active`

## 背景

排查「照这个再来一次」为什么不出现时，翻出一件更大的事：

**没有任何代码把 `shared_events.state` 写成 `completed`。**

而读的那一侧全都在等它：

- 森林里的「这件事做成了」（`counts_as_done = state == "completed"`）
- 成长档到「开花了」（`growth.of(completed=..., has_evidence=...)`）
- 「这次留下了什么」那一屏
- 「照这个再来一次」
- 关于我的记录能不能收割（`memory.py` 那条 `where state == "completed"`）

一整条下游建好了，源头那一笔从没落过——**而每一层单独看都正常**。
测试也是绿的，因为 fixture 直接写 `state="completed"` 造数据。

这是这个仓库反复出现的同一种毛病：**读的那一侧建完了，没人问过"谁写这一列"**。
匹配器那一侧已经有 `test_every_input_the_matcher_reads_has_a_real_user_writer`
在守着，事件状态这一列不在它的覆盖里。

## 决定

**`POST /spaces/{id}/done` 在「全员都标了」的那一刻，把事件置为 completed。**

```python
if screen.all_done:
    repos.events.complete(board.space.event_id)
```

### 一个人说完了不算

这件事会写进**每个人**的森林。让一个人替所有人宣布，等于让他替别人
在自己的经历上签字。

这和不变量 11 是同一条：AI 不能代为承诺，人也不能代替另一个人承诺。

### 还没齐之前能收回

不给收回的路，人就不敢点；而不敢点会让这一步整个失效。
收回的按钮也得有 44px——**一个点不中的后悔药等于没有后悔药**。

### `complete()` 只有一个调用者

它只被"全员各自说了做完"那一处调用。已经 completed 的返回 `False`：
重复调用不产生第二次完成。

## 后果

- `Repositories` 多了 `events` 这一格（原来 HTTP 层拿不到事件仓储）
- 三条测试守着：一个人说不算、全员说了才转、还没齐之前能收回
- 走查第⑨½幕从"两个人各自说做完"一路验到"下一颗种子发出去"

## 留下的做法

**建一条读路径之前，先问"谁写这一列"。** 这次是第五次栽在同一个坑上
（真人对话区没挂载、森林里的一株点不进去、「再来一次」在走不到的分支上、
投递范围没有界面入口、事件状态没有写入者）。

值得把匹配器那条 meta 测试推广到"所有被界面读取的状态列"。
