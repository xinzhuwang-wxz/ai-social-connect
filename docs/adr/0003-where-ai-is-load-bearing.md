# ADR 0003 · AI 承重的位置，以及由此重排的顺序

- 状态：已采纳
- 日期：2026-08-12
- 触发：自查"拿掉 AI，这个产品是否还成立"时发现答案难看

## 背景

赛题有一道必答题：**如果拿掉 AI，这个产品是否还能成立？**

按数据流顺序推进到 M2 时，已建成的 AI 只有意图编译——而它恰恰是唯一能被
一张表单完整替代的部分。也就是说，当时的答案是"成立"，这对一个以 AI 社交
为命题的产品是失败的答案。

## 判断

AI 出现在六处，其中**四处不可替代**：

| 位置 | 拿掉之后 | 可替代 |
|---|---|---|
| 意图编译 | 变成填表 | 是 |
| 成局证明转写 | 变成模板句 | 是 |
| **语义召回** | "写朋克风格文案"这类需求永远匹配不到——没有表单字段能表达它 | **否** |
| **受限协商** | 真人自己来回问 N 轮"你周四有空吗" | **否** |
| **行动回声** | 没人手写复盘，关系资产这条线断掉 | **否** |
| **记忆切面抽取** | 下一次匹配无从改善，闭环合不上 | **否** |

## 决定

**按"哪部分决定产品能否成立"排序，不按数据流顺序排。**

具体只有一处改动：**语义召回从"待建"提到群体求解之前**。它是四个不可替代
项里最靠前也最便宜的一个（本地 all-minilm，384 维，零外部凭证），并且它直接
回答"schema 装不下的长尾怎么办"。

其余三项位置不变，但协商层不再自研状态机（见 ADR 0004）。

## 理由

结构化 schema（目标/能出/缺/时间/地点/人数）覆盖硬约束，覆盖不了表达。
`raw_expression` 一直被完整保留，信息没丢，只是没参与匹配——接上 embedding
之后它就参与了，而且不需要有人事先想到"朋克风格"这个维度。

分层因此是清楚的：

```
硬约束（角色/时间/地点/人数）  →  SQL 过滤，精确，不可被软分抵消
说得出但装不进字段的           →  语义召回
说不清楚的                     →  抽取器追问，最多两个问题
根本不该被自动判的             →  留给真人（决策门）
```

## 后果

- 召回从"纯结构化"变成"结构化 + 语义"混合，与 03-技术架构 §8.3 的设计一致。
- 需要 pgvector 与一个 `Embedder` 端口。向量只索引**已授权**的内容。
- 高选择性下先过滤再精确比较，这仍是 pgvector 的舒适区（见 ADR 0002 同类判断）。
- 这条 ADR 不改变任何领域不变量，只改变实现顺序。
