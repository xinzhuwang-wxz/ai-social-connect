## 发生了什么

2026-08-12，仓库的工作目录 `/Users/bamboo/Githubs/social` 在会话之外被删除。
本地那十来个提交从未推送，git 历史随目录一起消失；远端停在当日 00:39。

代码从运行中的容器里完整捞回（两个镜像都是删除前最后一次构建打的），
**丢的是文档**：这一号、`docs/10-PRD对照.md`、`docs/11-PRD-v2-审查.md`、
`docs/prd/` 下两份 PRD、`docs/05` §5 后来追加的评审记录。

## 为什么不补写

0009、0010、0011 能重建，因为它们的判断**被代码引用着**——
`growth.py` 写着「ADR 0009」，`window.py` 写着「ADR 0010」，
issue #30 写着「ADR 0011 的判断保留」。顺着这些引用能把原来的论证找回来。

这一号在代码、文档、issue 里**一处引用都没有**。没有引用意味着两件事之一：
它记的判断后来没被任何代码依赖，或者它从一开始就没被引用过。
无论哪一种，**凭印象补写出来的都不是当时那条判断**，而一条读起来像 ADR、
内容却是事后编的记录，比缺一号危险得多——后来的人会拿它当依据。

## 编号不回收

0009 起的三条被代码按号引用。把这一号让给新决策会让「ADR 0008」
在两个时期指向两件事，而搜索代码注释的人分不出自己看到的是哪一个。

新决策从 0012 起。

## 这次事故留下的做法

**决策不能只活在未推送的提交里。** 从这次起，写下一条 ADR 之后就推送——
它的成本是一次 push，而它防的是"论证没了，只剩结论"。

issue 的关闭说明这次成了唯一的备份（#22–#31 那几条长说明救回了三条 ADR
的骨架）。**在 issue 里把判断写完整**这个习惯值得保留，它天然存在别处。
