# ADR 0011 · 私密评价是配对偏好，不是评分；回忆门控分层

## 背景

PRD 要求一次行动完成后，双方各自提交照片、一段文字，以及**是否愿意再次组队**。

"互评"这个词天然把人往评分系统上带：五星、好评率、信用分。
而一个校园社交产品一旦有了公开评分，它就变成了一个**声誉市场**——
分低的人再也约不到人，而分低的原因可能只是他第一次用。

## 决定

### 一、它是配对偏好，不是评分

「不愿意再一起」记成一条 `(A, B) 不再配` 的**私有记录**。

- **不可聚合。** 没有任何查询能算出"B 被多少人拒过"。不是"我们不查"，
  是**没有那个查询**——能算出来的东西迟早会被算出来展示。
- **只影响这两个人。** 求解器那边它就是 `excluded`，机制早就存在。
- **永不对外。** 不告诉对方是谁选的。

一个人的对外表示只由**共同事件**构成（不变量 7：关系图谱是共同事件的
可重建投影，不是主观判定）。别人对他的看法不进那个投影。

### 二、回忆门控分层

产品负责人的判断：**门控的是森林里对外那一份，不是池塘内部的 recap。**

| 哪一份 | 谁能看 | 要不要双方同意 |
|---|---|---|
| 行动房间内部的 recap | 这件事的成员 | **不要** |
| 森林里对外可见的共同回忆 | 这两个人之外的人 | **要，双方都愿意才生成** |

理由：房间内部那份记的是**在场的人都经历过的事**。为一件所有人都在场的事
再要一次授权，是把授权做成了仪式——而仪式化的授权会让人学会一路点确定，
那时候真正需要授权的那一次就废了。

对外那一份不同：它会出现在**不在场的人**眼前，那才是需要两个人都点头的地方。

## 为什么实现延后

闭环在「开花 → 森林里多一株」那里已经合上了。

私密评价要一张新表、两块新界面（评价表单 + 门控后的回忆页），
而它对故事的增量是"这次之后要不要再一起"——**一个只有在第二次才生效的东西**。
第一遍走通之前，它是长尾。

判断保留：将来做也照这个做。
