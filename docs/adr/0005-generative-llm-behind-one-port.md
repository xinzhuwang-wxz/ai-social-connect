# ADR 0005 · 生成式 LLM 走一个端口，用 litellm 做适配

- 状态：已采纳
- 日期：2026-08-12
- 相关：issue #8 #11 #12 #14，[ADR 0003](./0003-where-ai-is-load-bearing.md)

## 背景

到 M3 为止，代码里一处 LLM 客户端引用都没有。意图抽取是规则解析器，
语义召回是本地 Ollama 嵌入。这是对的——ADR 0003 判定意图编译是**可替代**的
位置，不该是第一个上 LLM 的地方。

但剩下三处不可替代的位置都需要生成式模型：受限协商的措辞、行动回声、
记忆切面抽取。它们绕不过去。

## 决定

**一个 `Composer` 端口，litellm 做适配器，火山方舟（豆包）与本地 Ollama 两个后端。**

端口的形状本身就是约束（见 `domain/ports/composer.py`）：

- **不接受提示词，只接受事实。** 调用方给一组已获准使用的事实，起草者从中写话
- **不能检索、不能调工具、不能读库。** 输入是封闭集合
- **返回 `Draft` 而不是字符串**，草稿带着它依据了哪些事实
- `DraftKind` 是枚举不是自由字符串，新增用途要显式加进来

## 为什么是 litellm 而不是直接用某家 SDK

因为我们**确实需要两个后端**，这是它有价值的唯一条件：

| 场景 | 后端 | 理由 |
|---|---|---|
| 开发与 CI | 本地 Ollama / 磁带回放 | GOAL.md 要求零外部凭证、CI 可离线 |
| 演示 | 火山方舟豆包 | 这是字节的赛题 |

只有一个后端时 litellm 是纯粹的多余抽象——嵌入那一层就没用它，
因为切换点已经在 `Embedder` 端口上了，再叠一层是两层抽象干同一件事。
生成这一层不同：磁带层要挂在**一个**地方，两个后端的调用约定必须先被统一。

**优先便宜模型。** 默认走豆包的轻量档；只有在轻量档明显写不好的位置才升档，
而且升档要写在调用点旁边说明理由。

## 为什么不用 LangChain / AutoGen / CrewAI

那类框架的核心价值是编排 agent 之间的**自由对话**，而我们整个设计建立在
相反的判断上：自由格式协商是攻击面（见 ADR 0004 附带证据）。用它们不但
帮不上，还得先把自由对话能力拆掉。

## CI 走录制回放，不是走 mock

"不用 mock/stub"是红线（R11）。但 CI 里调真模型有三个问题：要凭证、
不确定、要钱。

**磁带（cassette）是这两者之间唯一诚实的解**：录一次真模型的真输出存下来，
CI 回放。回放的内容**是真的模型写的**，不是我们手写的假货——这和 mock
的区别不是程度，是性质。

- 磁带按 `(kind, facts, instruction, model)` 的摘要索引
- 录制模式：未命中就真调用并写盘
- 回放模式（CI 默认）：未命中就**失败**，不静默穿透去调真模型
- `Draft.replayed` 如实标记，"这次真的调了模型吗"永远查得出

## 后果

- 凭证只从环境变量读，`.env` 已在 `.gitignore` 里，密钥永不入库
- 起草服务不可用时必须降级：`ComposerUnavailable` 是端口的一部分，
  不是异常情况。协商措辞降级成"对方需要你回复"，证明转写降级成模板，
  都仍然可用
- 换模型不触及任何领域测试。这条是判断边界画得对不对的标准
- 这条 ADR 不改变任何领域不变量。**AI 起草，人类决定**仍然由消费侧
  强制（`space_items.accepted_by`、承诺表只接受真人签名），
  端口只负责让"忘了要人确认"变成显眼的类型错误而不是静默默认值
