## 1. 六条产品决策（PRD v2 审查的结论）

产品负责人逐条定的，**不是全盘照做**：

| PRD 的要求 | 决定 | 为什么 |
|---|---|---|
| 投递制 | **采纳** | PRD 这一处比原实现对：旧链路让发起人挑一支队再等回音，而"石沉大海"正是要消灭的第二个痛点。见 [ADR 0010](./adr/0010-delivery-instead-of-group-solving.md) |
| 发起人只选**一名**同行者 | **不采纳** | 按种子要的人数收满为止。一件要三个人的事只让选一个，等于让人重复三遍整个流程 |
| AI 主动推进 | **改按钮触发** | 更克制，而且少一个定时器。见 issue #31 |
| 双方确认完成 | **采纳** | 见 [ADR 0012](./adr/0012-completion-needs-everyone-to-say-so.md) |
| 回忆门控 | **采纳，但分层** | 池塘内部的 recap 保留（成员本就都在场），受门控的是森林里对外那一份。见 [ADR 0011](./adr/0011-private-rating-is-a-pairing-preference.md) |
| PixiJS 画花园 | **暂不采纳** | 它带来 WebGL 运行时、资源管线与移动端性能风险，而规范自己写着"一个植物 = 一个清晰轮廓 + 2～4 个主要色块"——那正是 inline SVG 的舒适区。留作升级路径 |

## 3. PRD 明确没有覆盖、而我们坚持的三条

无论 PRD 怎么写，这三条不越（见 [`docs/GOAL.md`](./GOAL.md)）：

1. AI 可以代为表达，**但不能代为承诺**。承诺状态只接受真人签名的命令
2. 未获真人确认的提案不创建事件、共域或关系边
3. 稳定性检查未通过的分区不得成为提案
   （投递制下不存在分区，所以这条在那条路上**没有对象**，不是被放宽了——
   组织者招募那条多席位的路上它照旧守着）
