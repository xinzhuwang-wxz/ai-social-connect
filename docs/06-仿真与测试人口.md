# 共域 CoField · 仿真与测试人口

- 面向：在没有真实用户之前，如何让匹配系统真的跑起来、并且测出真问题
- 与其他文档的关系：机制见 [`03-技术架构`](./03-技术架构.md)，指标见 [`02-产品设计`](./02-产品设计.md)

---

## 1. 为什么静态测试数据不够

共域是一个**市场**。市场的关键性质——会不会挤兑、窗口该多长、冷启动会不会被压死、多少人才够开自动成局——只有在参与者**会反应**的时候才浮现。

一批静态用户记录能测的：管道通不通、SQL 过滤对不对、界面渲染正不正常。
它测不出的：上面每一个真正决定产品成败的问题。

所以人口分三层，不是一层。

```
L0  静态种子人口     系统跑起来、可演示、测管道
L1  行为仿真人口     市场跑起来、扫参数、发现结构性缺陷
L2  真人小规模       校准 L1 的行为参数，验证仿真没有自欺
```

**L1 的参数必须由 L2 校准，否则仿真结论不可信。** 游园会是 L2 的天然场合。

## 2. L0 静态种子人口

### 2.1 规模：人口全量，活跃度按渗透率

这是本文最重要的一个数字决定。

| | 数量 | 理由 |
|---|---|---|
| **校园总人口** | **20,000**（对齐真实校园规模） | 硬约束过滤的**选择性**只有在真实人口下才真实 |
| **同时活跃的意图** | **200–600**（1–3% 渗透率） | 真实产品的渗透率就是这个量级 |
| **组织者** | 8–12 | 供给侧不能空，否则漏斗第一段空转 |
| **行动机会** | 30–60，带真实席位结构与期限分布 | 同上 |

**为什么不能只造 2,000 人**：2 万人过滤到几百是 1.5% 选择性，2 千人过滤到几百是 15%。这两个数字会导出完全不同的结论——pgvector 的 pre-filter 判断、召回深度、曝光集中度、稀缺角色瓶颈，全部测错。

**为什么活跃意图不能按 2 万算**：真实产品不会有 2 万人同时挂着意图。按渗透率取 200–600，才能测出**薄市场**——而薄市场恰恰是这个产品最可能死的地方。

**成本控制**：2 万份结构化档案用 Faker + NetworkX 生成几乎不要钱；只对**当前活跃意图池**（200–600 条）用 LLM 生成自然语言文本。既真实又便宜。

### 2.2 四个维度不能随机

这是把系统测得过于乐观的四个陷阱：

| 维度 | 真实形态 | 随机生成的后果 |
|---|---|---|
| **技能分布** | 长尾。会写文案的几百人，会调色的十几个 | 角色覆盖约束假性容易满足，看不出稀缺角色是瓶颈 |
| **时间可用性** | 由课表决定，冲突高度集中 | **最危险的一个**——均匀随机的时间几乎总能找到交集，时间约束形同虚设 |
| **社交网络** | 有社区结构，同班同社团聚集 | 跨圈层桥接的价值和曝光集中都测不出来 |
| **意图到达** | 截止期前扎堆，不是均匀泊松 | 撮合窗口的效果完全测错 |

社交网络这一条正好和领域模型同构：**用 NetworkX 生成学生 × 课程/社团的二部隶属网络，再投影出人-人网络**。生成器和产品用的是同一个结构（Breiger 二重性），不是两套假设。

### 2.3 优先真实公开数据，再退合成

分布不要凭空拍。可获取的公开结构应当先用：

- 专业与年级分布（招生简章、院系页面）
- 课程时间结构（公开课表的时段模式，不需要具体学生数据）
- 社团规模分布（社团联页面）
- 竞赛与截止期日历（校历、赛事公告）

**合成只用于填补拿不到的部分。** 拿到真实分布的维度要在生成器里标注来源，方便日后复核。

### 2.4 历史分层

```
45%  零历史            验证冷启动公平（demo 主角必须来自这一层）
35%  1–3 个事件切面     验证证据如何进入成局证明
20%  重复协作历史       验证长期记忆的增量价值
```

### 2.5 意图文本必须用 LLM 生成，但只用于文本

意图编译是产品第一环，要测它就必须有**自然语言表达**，不能只有结构化字段。

```
结构化字段              →   LLM 反向生成口语化表达
goal: 60秒短片              "想拍个一分钟的校园流浪猫，周五交"
needs: [拍摄, 剪辑]          "我能写本子，但不会拍也不会剪"
```

要刻意生成**表达质量参差**的样本：清楚的、含糊的、夹杂无关信息的、自相矛盾的（"周五截止"但"下周有空"）。抽取失败的降级路径只能靠这些测到。

**LLM 的职责严格限定在生成文本，不参与任何决策**（原因见 §5.1）。

## 3. L1 行为仿真：只有这层能回答的问题

| 问题 | 仿真设计 | 判据 |
|---|---|---|
| **撮合窗口该多长** | 扫 1h / 6h / 24h / 48h | 成局率 × 完成率 − 等待流失 |
| **稳定性检查值不值** | 开关 A/B | 成局后至首次行动前的退出率差异 |
| **曝光会不会挤兑** | 观察分布基尼系数 | 前 10% 候选拿走的提案比例 |
| **冷启动是否被压制** | 分层对比 | 新用户 vs 老用户的首次成局时间差 |
| **谎报 deadline 的影响** | 引入策略型 agent | 谎报者收益 vs 系统整体成局率 |
| **流动性阈值在哪** | 扫活跃意图池规模 | 可行提案率跌破阈值的临界人数 |
| **稀缺角色瓶颈** | 扫技能分布尾部厚度 | 哪个角色缺口最先导致无解 |

最后两条直接决定上线策略——**一个校园要有多少活跃意图才能开放自动成局**，这个参数只能靠仿真找。

### 3.1 仿真 agent 的行为模型

agent 必须会：

- 按自身偏好接受 / 条件接受 / 拒绝
- 在两个提案之间挑更好的（**这才能激活稳定性检查**）
- 因时间冲突或目标改变中途退出
- 一部分（比例可配）谎报紧急度

**行为参数化，不用 LLM 决策。** 参数初值靠常识设定，之后由 L2 真人数据校准。

### 3.2 工具

| 用途 | 选择 | 许可 |
|---|---|---|
| ABM 框架 | **Mesa** | Apache-2.0，Python ABM 的标准选择 |
| 备选 | AgentPy | 交互式实验与数据分析一体 |
| 排队/等待专项 | SimPy | 离散事件仿真 |
| 隶属网络 | **NetworkX** | BSD |
| 基础属性 | **Faker / Mimesis** | MIT |
| 合成表数据 | SDV | 有真实数据后用于拟合分布 |
| 意图文本 | 复用产品自己的结构化输出管线，反向使用 | — |

## 4. 两个必须现在就定的架构约束

### 4.1 Clock 端口

要做时间快进，**领域核心不能直接调 `now()`**。

```
Clock 端口
  ├─ SystemClock      生产
  ├─ SimulatedClock   仿真，可任意快进
  └─ FrozenClock      单元测试
```

意图 TTL、撮合窗口、切面有效期、提案过期、工作流等待——全部走这个端口。

> **这个如果现在不加，以后就加不进去了。** 它现在是一行接口，三个月后是一次跨几十个文件的重构。

### 4.2 合成主体标记与隔离

```sql
principals.is_synthetic  boolean not null default false
```

配套三条硬约束：

1. **合成主体永远不能与真人进入同一个成局提案**（领域不变量，写进测试）
2. 仿真跑在独立 `campus_id` 上，与真实租户物理隔离
3. 界面上合成主体必须可见标记

第三条是治理要求，不只是工程隔离——**不能让真人以为自己在跟真人匹配**。

## 5. 仿真的诚实边界

三条，第三条最重要，必须写进团队共识。

### 5.1 LLM agent 有"生成式夸张"

2026 年的研究明确指出，LLM 驱动的社会 agent 决策比真人更极端、更一致，并存在 persona drift 与刻板印象放大。学界共识是：LLM 适合**生成合成数据和原型化社会动态**，但不是人类认知的可靠替代品，方向是**混合**——用仿真增强而非替代真人验证。

→ 因此 LLM 只生成意图文本，不做接受/拒绝决策。

### 5.2 仿真里没有社会成本

真人拒绝一个同学是有心理负担的，agent 没有。所以仿真中的拒绝率、体面拒绝使用率、条件接受比例都会失真。这些指标只能由 L2 校准。

### 5.3 仿真只能排除坏设计，不能证明好设计

> 仿真人口的分布是我们自己写的，**它会验证我们的假设，不会推翻它**。

- 仿真显示某参数下系统崩了 → 可信的坏消息，照做
- 仿真显示某参数下系统很美 → 只说明"在我们假设的世界里它很美"

**不得将仿真结果作为产品有效性结论对外表述。**

## 6. L2 真人校准

规模 20–50 人，一轮完整流程。要采集的校准量：

| 校准项 | 用途 |
|---|---|
| 提案查看→响应的转化率与时延 | 校准 agent 的响应模型 |
| 拒绝率与拒绝方式分布 | 校准 §5.2 的社会成本缺失 |
| 条件接受的实际比例与常见条件类型 | 校准协商模型 |
| 成局后至首次行动的流失率 | **校准稳定性检查的真实收益** |
| 意图表达的真实质量分布 | 反过来修正 L0 的文本生成器 |
| 回声确认率与拒绝理由 | 校准记忆治理的接受度 |

游园会满足条件：几百个同龄真人同处一地、同一时间窗、有真实的组队需求。**这是把"我们论证它会有效"升级为"它现场真的连上了 N 组人"的唯一机会。**

## 7. 落地顺序

```
1. Clock 端口 + is_synthetic + 仿真租户        ← 架构决定，必须在写领域代码之前
2. L0 生成器：NetworkX 隶属网络 + Faker + 公开数据校准分布
3. 活跃意图池 LLM 文本生成（200–600 条，含劣质样本）
4. 漏斗跑通 → demo 可用 → 游园会可体验
5. L1 Mesa 仿真，扫窗口 / 稳定性 / 流动性三组参数
6. L2 游园会真人数据，回头校准 L1
7. 用校准后的 L1 定上线策略（多少活跃意图才开放自动成局）
```

第 1 步是唯一有硬时间窗口的。
