# 终局与推进循环

这一页是长期站着的作战简报。设定 `/goal` 后按它自主推进；每次准备停下来之前，用页尾的「未达成即未完成」对一遍。

---

## 终局

> **一个没读过任何文档的大二学生，打开产品说一句话，能一路走到"我们把这件事做成了"，并在两周后因为一条他自己批准过的记录被再次找到。**

具体到可判定的状态：

1. 一个**零历史**的学生输入一句自然语言，得到一张可修改的需求卡
2. 他逐项决定这次露出什么，能预览别人会看到他的什么
3. 到了配队窗口，他拿到 **2–3 个小队**，每队附**可逐条追溯**的理由，且没有任何百分比
4. 被邀请的一侧看到的是"这次我会得到什么"，可以有条件接受，也可以零负担拒绝
5. 全员确认后，共域在**一个事务内**诞生；未达门槛则什么都不产生
6. 行动结束，逐项确认后形成带来源与有效期的记录
7. 两周后他发起新需求，成局证明里出现"你们上次一起完成过 X"

**这七步在合成校园（2 万人口 / 200–600 活跃需求）上跑通，且每一屏都能被一个没读过文档的人独立走通——这就是终局。**

不在终局里的：多校园、外部 Agent 生态、学习排序、商业化、完整组织者工作台。

---

## 循环

设定 `/goal` 之后自主运行，逐 issue 实现并提交，不停下来问下一步做什么。

```
实现 milestone 的 issue（逐个提交）
        ↓
架构审视      用 codebase-design 词汇找 deepening 机会
        ↓
/verify       确认在轨且不冗余
        ↓
提交推送      提交信息说明这个里程碑改变了什么判断
        ↓
下一个里程碑
```

**只在一种情况下停下来找人**：某个决定如果做错会导致整个里程碑返工。其余决定自己定，写进 `docs/adr/`。

HANDOFF「待你决定」的 6 项属于自己定的范畴，不是阻塞项。

## 「在轨」的定义

`/verify` 每次必须回答这四条，任一为否即偏离：

1. **本里程碑所有 issue 的验收标准全绿**，不是"差不多了"
2. **13 条领域不变量测试全绿**（见 PRD Testing Decisions）
3. **没有引入 [`HANDOFF.md`](../HANDOFF.md) 「别重开」清单里的任何一项**
4. **闭环没有被为了赶进度而切断**——任何一片都不能以"先跳过回流"为代价通过

第 4 条是最容易失守的。前 13 片都在铺路，如果为了让某片好做而砍掉尾部，整个产品的论点就没了。

---

## 「不冗余」的定义

同样每次 `/verify` 检查，用 `codebase-design` 的词汇表述：

1. **没有为测试而造的假实现。** 唯一被替换的是"人"——真 Postgres、真 CP-SAT、真 pgvector、真 LLM（CI 走录制回放）
2. **没有第二数据源。** Postgres 是唯一权威，向量与图投影可随时重建
3. **没有手写类型。** Pydantic → OpenAPI 3.1 → 前端类型自动派生，三层同名
4. **没有为新场景新增的领域核心文件。** 场景差异落在行动类别注册表
5. **每个新 adapter 至少有两个真实调用点。** 一个 adapter 是假想的 seam，两个才是真的
6. **没有孤儿抽象。** 通不过删除测试的模块就删掉

## 终局验收：UI-only autoresearch

M4 通过后执行。**只通过界面操作，不读代码、不调 API、不看文档**——像一个刚下载完的学生。

直接喂给 `/autoresearch` 的五项配置：

```
Goal:
  一个没读过任何文档的人，仅靠界面能独立走通「说一句话 → 拿到小队 →
  确认成局 → 推进项目 → 留下记录 → 被再次找到」全链路，
  并能在结束后用自己的话说出这个产品是干什么的。

Scope:
  仅限用户界面。禁止读源码、禁止直连 API、禁止查阅 docs/。
  运行在合成校园租户上（campus_id = simulation），
  真人 persona 与合成人口交互，合成主体带可见标记。

Direction:
  逐个 persona 走完全链路，记录每一次卡住、每一次看不懂、每一次想放弃：
  1. 大一新生，零历史，不知道这产品能干嘛
  2. 慢热的大三技术生，有能力但不想主动开口
  3. 赶 deadline 的发起人，只剩两天
  4. 社团组织者，要为比赛凑三支队
  5. 隐私敏感者，想知道系统记了自己什么、能不能删干净
  6. 收到邀请但想拒绝的人
  7. 中途要退出的成员
  8. 完成过一次、两周后回来的人

Metric:
  每个 persona 的：
    blocked_steps    卡住次数（无法继续或走错方向）
    confusion_hits   看不懂的文案条数
    abandon_points   会真的放弃的位置数
    term_leaks       界面上出现领域词汇的次数
    missing_states   五态缺失数（首次/加载/空/错误/降级）
  总分 = 五项加总，越低越好。终局目标：全 persona 总分 = 0。

Verify:
  pnpm e2e:persona-walkthrough --report
  输出 JSON，取 total_friction 字段作为可测数值。
  （这个脚本本身在 M4 内建好，它是终局验收的一部分，不是事后补的。）

Guard:
  pnpm test && pnpm typecheck
  不允许为了降低 friction 分而破坏任何领域不变量。
```

**判定**：任一 persona 在任一步骤上卡住，都算未通过。产品不是给读过 163 条用户故事的人用的。

**这一关必须能失败。** 如果 autoresearch 从来没判过不合格，说明量表设松了——`e2e:persona-walkthrough` 在 M4 内建好而不是事后补，就是为了避免它被写成"能跑通就行"的形状。

---

## 三条不可越过的约束

无论进度多紧：

1. **AI 可以代为表达，但不能代为承诺。** 承诺状态只接受真人签名的命令
2. **未获真人确认的提案不创建事件、共域或关系边**
3. **稳定性检查未通过的分区不得成为提案**

其余的一切——包括代聊是否披露、撮合窗口多长、稳定性用哪个概念——都是可配置策略，不是红线。

## 起手

设定 `/goal`（内容见本页「终局」与「未达成即未完成」两节），然后从 M0 · issue #1 开始，自主推进到 M4，最后跑终局验收。

## 完成的定义：三个维度全绿才算

### A. 完整——没有半条路

- [ ] 七步终局链路端到端跑通，没有任何一步是演示用的假实现
- [ ] 16 个 issue 的验收标准逐条全绿
- [ ] 每一屏五态齐全：首次 / 加载 / 空 / 错误 / 降级
- [ ] 13 条领域不变量都有测试且全绿
- [ ] 代码里没有 TODO、没有占位实现、没有"以后再说"的分支
- [ ] 降级路径真的能降级：LLM / 向量 / 实时 / 助手任一挂掉，用户仍能保存需求、看空间、人工确认、上传证据

### B. 可扩展——用测试证明，不用形容词

- [ ] 新增一个行动类别不改领域核心的任何一个文件（回归测试证明）
- [ ] 所有状态可通过版本化 API 完整获取；换一个前端不需要动后端
- [ ] 换 LLM、换向量后端、换求解器实现，领域测试一条都不用改
- [ ] Postgres 是唯一权威；向量与图投影删库能重建
- [ ] 容量护栏在两万人合成校园上实测过，估计值已替换为实测值
- [ ] 租户隔离有测试：合成主体不与真人同局，跨租户读取被拒

### C. 经真实检验——autoresearch 有权判不合格

- [ ] 8 个 persona 的 UI-only autoresearch 总摩擦分 = 0
- [ ] `e2e:persona-walkthrough` 量表在 M4 内建好，不是事后补的
- [ ] autoresearch 报出的每一个卡点都有对应的修复提交，没有被记成 issue 放过
- [ ] `pnpm test && pnpm typecheck` 全绿

**这一关不是盖章，是可以不通过的。** 失败就回到对应里程碑重做。
