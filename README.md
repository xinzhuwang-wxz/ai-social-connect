# 共域 CoField

**以共同事件为核心的校园社交连接器。**

不是校园通讯录、校园墙、陌生人卡片推荐，也不是让两个数字分身替真人交朋友。它解决的是：

> 当一个学生只有"此刻想做什么"，却没有完整资料、现成关系和主动破冰能力时，系统如何把模糊意图变成可回应的行动条件，找到一个真正能成事的小组；又如何在所有真人确认后，把这次行动变成多人共同拥有的空间和下一次连接的可信依据。

```text
当下意图 → 匹配信封 → 成局提案 → 受限协商 → 真人共同承诺
        → 共同事件与共域 → 行动证据与回声 → 可撤销的记忆切面 → 更好的下一次成局
```

## 三个标志性机制

**成局证明** —— 输出的不是"你们有 92% 相似"，而是"这组人为什么有能力、有时间、有互惠价值地把事情做成，还差哪些真人决定，以及为什么没有人有更好的去处"。

**N+1 共域** —— 真人确认后，匹配期的个人意图使者退出，一个只属于共同事件、由 N 名成员共同约束的场域智能体诞生。它属于关系，不属于任何一个人。

**行动回声** —— 作品、照片、任务结果和复盘，经相关人员确认后形成有来源、有权限、有时效的记忆切面。空间因此生长，未来匹配也因此变得更可信。

## 底层逻辑

> **系统里没有"用户档案"这个对象。只有事件，和从事件投影出来的人与关系。**

四条不变量：

1. 事件是一等公民，人是事件的投影
2. 意图不是画像的降级版，是另一类对象
3. 权威事实与派生索引严格分离
4. 熟不熟是算出来的，不是存出来的

这不是设计偏好，分别对应 Breiger 人-群二重性、超图、EBSN 三个成熟结论。详见 [`05-研究依据与评审`](./docs/05-研究依据与评审.md) §1。

## 工程红线

**1. 复用优先，不重复造轮子。**
只自研四个差异化岛屿：领域协议、互惠求解+稳定性检查+成局证明、共域与 N+1 权限、结果反馈闭环。认证、数据库、存储、实时、协作编辑、工作流、策略引擎、结构化输出、约束求解、可观测性、Agent 协议一律先评估成熟上游。标准复用同理——同意记录直接采用 ISO/IEC TS 27560:2023，不自创 schema。

**2. 后端是产品本体，前端可替换。**
所有状态必须能通过版本化 API 完整获取。实时通道是增强而非必需。

**3. 场景差异落在注册表，不落在代码分支。**
新增一个行动类别（短片创作 / 比赛组队 / 夜爬 / 学习搭子）应该只是新增一份注册表条目。**如果加新场景需要改领域核心的任何一个文件，说明扩展点设计错了。**

**4. Agent 起草，人类决定。**
Agent 不自动披露、邀约、接受、承诺、建群或发布共同记忆。数据库仅接受真人签名的同意命令。

**5. Postgres 是唯一权威。**
向量、图、搜索、Agent memory 全部是可重建的派生物。不能以"向量库里搜得到"证明用户已同意。

**6. 契约先行，对齐靠脚本不靠人眼。**
Pydantic 领域 schema → FastAPI 导出 OpenAPI 3.1 → 前端类型自动派生，任何一层都不手写类型。一个概念在 DB / API / 前端用同一个名字，命名来源是 CONTEXT.md。

**7. 领域核心不得直接调 `now()`。**
时间是注入的 Clock 端口，否则仿真无法快进——这条必须在写领域代码之前定。

**8. 领域词汇不得出现在界面上。**
"同意凭证""记忆切面""成局证明"是代码和文档的语言，不是用户的语言。严谨性要能被感受到，不能被阅读到。映射表见 07，CI 应对用户可见文案做术语黑名单检查。

## 已锁定的关键决定

| 维度 | 决定 |
|---|---|
| 社交基本单位 | 共同事件 / 临时共同体，不是个人资料卡 |
| 关系的数学对象 | 超边，不是两两边（这是 N+1 的根据） |
| 首个楔子 | 项目、比赛、科研、创作组队 |
| 匹配目标 | 群体可行性 + 互惠 + **稳定性**，不是两人相似度 |
| 撮合节奏 | 固定窗口清算 + 截止期临近者提前处理，不是即时撮合 |
| 权威存储 | PostgreSQL 18+ + 领域事件账本 |
| 图 | 递归 CTE → 按需 Apache AGE，**不引入独立图数据库** |
| 向量 | pgvector + pre-filter 精确检索 |
| Agent 协议 | A2A 只用于跨信任边界；治理层自建（协议表达不了） |
